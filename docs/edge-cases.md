# Edge Cases & Validation

[Back to Wiki](README.md)

This page documents how the application handles edge cases, validates input, and recovers from errors.

## Data Upload Validation

| Check | Rule | Error message |
|-------|------|---------------|
| File type | Only `.csv`, `.xlsx`, `.xls` accepted | "Unsupported file type" |
| Empty file | Must have at least 1 data row | "No data rows found" |
| Minimum data | At least 5 valid data points | "Need at least 5 valid data points" |
| Date column | Must contain parseable dates | Auto-detection fails, user must select manually |
| Value column | Must contain numeric values | Non-numeric rows are silently filtered |
| Excel sheets | Only first sheet is read | — |

### Column Auto-Detection

The upload page matches column names case-insensitively:

- **Date columns:** `date`, `datum`, `time`, `timestamp`, `period`
- **Value columns:** `value`, `potrosnja`, `potrošnja`, `consumption`, `amount`, `spend`, `quantity`

If auto-detection fails, the user can manually select columns from dropdowns.

## Forecast Edge Cases

### Train/Test Split

| Condition | Behavior |
|-----------|----------|
| `data.length > horizon + 10` | Normal split: last `horizon` points as test set |
| `data.length <= horizon + 10` | No test set; metrics will be null/undefined |
| `data.length < 5` | Forecast may fail or produce unreliable results |

### MAPE Calculation

- **Zero values in actual data:** Skipped to avoid division by zero
- If all actual values are zero, MAPE is not calculated

### Auto ARIMA Grid Search

- Skips combinations where both `p=0` and `q=0` (invalid ARIMA)
- Catches convergence failures for individual (p,d,q) combinations
- Validation set: last 10% of data, minimum 5 points
- If no combination converges, falls back to default (2,1,2)

### ARIMA (WASM)

- WebAssembly module must load before first use
- Large datasets may cause browser to become unresponsive (mitigated by `runAsync()` yielding)

### Prophet (Server-Side)

| Scenario | Handling |
|----------|----------|
| Backend not running | Fetch fails; error message shown to user |
| Network timeout | Standard fetch timeout applies |
| Data < 10 points | Returns predictions but no metrics |
| Invalid date format | Prophet may throw 500 error |

## Compare Mode Error Handling

- Models run **sequentially** (not parallel) to avoid overwhelming the browser
- Each model is wrapped in try/catch — **one model failing does not block others**
- Failed models show "Error" badge in results table
- Success notification shows count: "5/6 models finished"
- At least 2 models must be selected to compare

## State & Persistence

| Scenario | Handling |
|----------|----------|
| Corrupt localStorage JSON | Falls back to empty initial state |
| User not logged in | State is not persisted (in-memory only) |
| Dataset deleted | Associated forecasts also deleted; active dataset reset if needed |
| Browser refresh | State restored from localStorage (if user logged in) |

## Chart Edge Cases

- If a model returns predictions without dates, dates are auto-generated by incrementing from the last historical date
- Maximum 12 x-axis labels shown (auto-thinning)
- Last historical data point is duplicated as first forecast point for visual continuity

## Known Limitations

1. **No server-side data storage** — all data lives in localStorage. Clearing browser data loses everything.
2. **Single-tab assumption** — no cross-tab synchronization of state.
3. **Excel: first sheet only** — multi-sheet Excel files only process the first sheet.
4. **CORS wide open** — backend allows all origins (fine for dev, should be restricted in production).
5. **No authentication on backend** — anyone can call the Prophet API endpoint.
6. **Prophet confidence intervals** — only Prophet returns lower/upper bounds; client-side models do not.
7. **Auto ARIMA performance** — grid search over 75 combinations can take 10-30 seconds on large datasets.
